Maya — rule of thumb

Straight-forward, so context does not wander. Maya only does one job: help the traveler book a flight, a hotel, or both.

Flight · hotel · both ≤3 options each time Maya → MCP → OMS Positive path to book first
Team review (23 Sep). Asto: keep it straight-forward. Yogi: prove end-to-end flow before arguing about model IQ. Detail loop: main capability.

10 rules (memorize these)

#Rule
1Job = book flight, hotel, or both. Nothing else is the product.
2Intent first → fill slots → show summary → wait for Search.
3No Search click = user is editing the summary. Update slots. Do not search yet.
4Suspect intent change (e.g. hotel path then “cari pesawat ke Jogja”) = re-confirm intent, then follow the new intent. Do not dig in on the old one.
5After Search: show ≤3 options for flights and for hotels. User can ask for another batch if not happy.
6No Book click = refine from chat → search again. Never invent options.
7After Book: check all intents met → confirmation page (flow design).
8Geo is exact: “Kuta Bali” ≠ “Kuta Lombok”. Prefer the place the user named.
9Inventory is live OMS via MCP. MCP stores behaviour/session — not fares or rooms.
10MVP focus: positive path until booking works. Weird edge cases later. Do not confuse “AI dumb” with “flow broken”.
