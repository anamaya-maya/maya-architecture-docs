Maya architecture & capability map

Maya’s job is only two outcomes: book a flight, a hotel, or both. Everything else is supporting that loop — intent → summary → search → ≤3 options → book → confirmation. Technical path: Traveler → maya-api → Anamaya MCP → OMS.

One-line technical truth

MCP is the gateway + session/behaviour surface for agents. Flight and hotel inventory is always queried live from OMS — it is not cached as inventory inside MCP.

Session / behaviour Intent, slots, trip summary, in-chat picks, reply pack (NRCP).
Live OMS via MCP Flights, hotels, rates, photos, policy, bookings, approvals.
Hard gates Book / pay / cancel need explicit traveler CONFIRM — pack text cannot weaken them.
Honest empty Empty OMS discovery → say so; never invent fares, hotels, or tickets.
