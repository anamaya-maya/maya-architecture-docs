What lives where

Yogi’s reading for inventory is correct: offers always come from OMS. MCP exposes the capability; it is not the source of truth for fares or rooms.

Concern Where it lives Does MCP store it?
User intent, slots, trip summary maya-api conversation state + memory Session / behaviour — yes
Chosen flight / hotel in this chat maya-api session state Choice context — yes
Reply style / NLU pack Natural Reply Capability Pack (SPEC-016/017) No — pack store / control plane
Live flight offers & prices OMS POST /flight/search/* No — queried each search
Live hotel discovery / rates / photos OMS hotel discovery / room-rate / property No — queried each search
Policy, ESPPD, approvals, e-ticket OMS booking / policy APIs Proxied on demand — not an inventory DB
Empty hotel list after training usually means OMS discovery empty for that geo, DNS split-brain, or conversation focus bug — not a missing MCP hotel cache.

Misconceptions to avoid

MisconceptionReality
MCP is a database of flights/hotels MCP is a tool/REST facade over live OMS. Inventory stays dynamic in OMS/Biztrip.
Maya AI → OMS directly Preferred path is Maya → Anamaya MCP → OMS. Direct OMS is fallback for paths MCP does not expose yet.
Empty hotel list means MCP “forgot” hotels Usually OMS empty geo, DNS, or focus bug — not an MCP inventory miss.
Behaviour pack = booking rules NRCP controls how Maya speaks. Book / pay / cancel stay hard-gated in tools (CONFIRM).
