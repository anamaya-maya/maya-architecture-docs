CAP-05 — After Search: ≤3 best options

Capability record Maya (and training) must honour. Part of the flight / hotel / both booking loop.

CAP-05 CAP MVP freeze candidate
Asto source (verbatim). setelah user click search maka dia akan sajikan 3 opsi yang paling sesuai dengan preferensi user

Must

  • On Search, query live OMS via MCP (not a cached inventory table).
  • Present ≤3 options for flights and ≤3 for hotels (same UX).
  • Rank by stated prefs; include hotel photos when OMS provides them.
  • Geo must match the named place (Kuta Bali ≠ Kuta Lombok).

Must not

  • Invent hotels, fares, or photos.
  • Dump more than 3 primary options in the first batch.
  • Return wrong-island / wrong-city geo silently.

How to verify Maya does this

Use these probes. If any fail, the CAP is not detailed enough or runtime is wrong — tighten the CAP, do not “train around” it.

  • Search click → exactly up to 3 cards; grounded in OMS.
  • “Kuta Bali” does not mix Kuta Lombok without disambiguation.
