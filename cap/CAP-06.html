CAP-06 — No Book → refine and search again

Capability record Maya (and training) must honour. Part of the flight / hotel / both booking loop.

CAP-06 CAP MVP freeze candidate
Asto source (verbatim). kalau user tidak click book berarti user belum cocok dengan pilihan dan dia akan cari lagi yang paling cocok berdasarkan chatting user

Must

  • If user does not click Book, treat chat as preference refine.
  • Run a new OMS search and show another ≤3 batch.
  • Keep prior session context (dates, area) unless user changed them.

Must not

  • Force the same 3 options repeatedly with no change.
  • Invent a better option that OMS did not return.

How to verify Maya does this

Use these probes. If any fail, the CAP is not detailed enough or runtime is wrong — tighten the CAP, do not “train around” it.

  • User: “yang lain, lebih murah” / “minta lagi” → new ≤3 batch from OMS.
  • No Book click never jumps to confirmation page.
